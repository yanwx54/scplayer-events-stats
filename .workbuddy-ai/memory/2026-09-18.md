### 关键技术发现（重要，可复用）
1. **Bash 沙箱无直连外网**，但环境变量已配代理 `http_proxy=http://127.0.0.1:1256`。
   - `curl` 走该代理会卡在 TLS 重协商（schannel）→ HTTP 000，**不可用**。
   - **Node 原生 `fetch` 走同一代理完全正常**（OpenSSL 栈），所有抓取脚本用 Node fetch。
2. **本地预览时 curl 访问 127.0.0.1 会被代理拦截** → 必须加 `--noproxy '*'` 才能访问本机服务。
3. eloboard 公开 JSON API（无需过盾，与官网前端同源）：
   - `GET /api/matches?event_id={43|33|64}&limit=200&offset=n`
     - `limit` 上限 **200**（201 即报错）；总数在响应头 **`x-total-count`**
   - `GET /api/players/{id}` — `main_race` / `elo_raw` / `thumb_url` / `college_name`
   - `GET /api/events/{id}` — 赛事元信息
   - 头像基址 `https://eloboard.co.kr/static/`（`.co.kr`，不是 `.com`）
   - 注意：旧文档说的 `/api/events/{id}/matches` **不存在**（404）
4. 比赛记录为**单局粒度**，`participants` 恒为 2 人，`elo_delta` 恒为胜方正增益（235 场为 null）。
   赛事 43/33/64 均为 `is_team_entry: true`（队制赛事），`participants[].team_name` 可拿到队伍。

## 追加：每日 10:00 自动同步

用户要求「以后每天 10:00 同步这三个网址更新的战绩，并更新数据库」。

### 新增 `scripts/sync.mjs`（增量同步）
1. 从 `offset=0` 分页拉取（官方最新在前），逐页比对本地已知 `match id`。
2. `REFRESH_WINDOW = 400`：最近 400 条**每次强制重抓**，用于吸收官方对近期记录的修正/删除。
3. 越过窗口后遇到「整页都已存在」即停止 → 增量边界。
4. 合并规则：`Map` 以新抓到的覆盖同 id，旧记录保留（只增不减 + 窗口纠错）。
5. 自动补抓新选手元数据、下载缺失头像，最后 `spawn` 调用 `build-db.mjs` 重建。
6. 输出 `SYNC_OK` / `SYNC_FAILED`；若本地条数 < 官方 `x-total-count` 会提示用 `--full`。
- 参数：`--full` 全量重抓、`--no-build` 只抓不重建。
- 实测：无新数据时 2.5~5s（每赛事仅 2 页）；**已用「删掉最新 7 场再同步」验证能精确补回，恢复后与备份 JSON 完全一致**。

### 自动化
- 名称「SC三大赛事数据每日同步」，id `6d509d81-1957-43f4-be6a-80da6aa7fa96`
- RRULE `FREQ=DAILY;BYHOUR=10;BYMINUTE=0`，cwd = 项目根，下次运行 2026-09-19 10:00
- 流程：`sync.mjs` → 失败则 `--full` → `verify.mjs` → 输出中文简报（≤12 行）
