### 核心发现（均已实测取证）

**🔴 P0-1 `verify.mjs` 失败不返回非零退出码 → 校验闸门失效**
- `scripts/verify.mjs` 全文**没有 `process.exit`**，结尾只 `console.log('VERIFY_DONE')`
- `deploy/self-sync.sh:71` 的判定是 `| tail -1 | grep -q VERIFY_DONE` → **永远命中**
- 即「校验不通过就不发布」这条保证对 verify 这一层是**假的**（verify-range 那层有效，会打 RANGE_FAILED）
- 修法：统计 ✗ 数，`fail>0` 时打印 `VERIFY_FAILED` 并 `process.exit(1)`；self-sync 改判退出码

**🔴 P0-2 `college` 字段零测试覆盖（已真实造成线上回归）**
- `grep -c college`：`verify.mjs` = 0，`shoot.cjs` = 0，`build-db.mjs` = 4
- 而 `build-db.mjs:154` 写入、`app.js:583` **前端正在展示**
- 这正是 9-20 那次 56 人战队名变 null 却通过全部校验的直接原因

**🟠 P1 三组**
1. **两条发布链路互相覆盖**：本地 10:00 `push-server` vs 服务器 10:20/20:20 `self-sync`，
   各自用**独立 `data/raw/`** 构建同一份数据 → 谁后跑谁赢。
   实测：线上 4033 场/截至 9-20，本地与 GitHub 均 4018 场/截至 9-18（服务器已领先）
2. **部署令牌走明文 HTTP**：`http://…:5001/api/deploy` + Bearer，令牌可写全站，路径上可嗅探
3. **静态资源 `no-cache` 且无 ETag/Last-Modified**（实测响应头确实两者皆无）
   → 重复访问无法 304，头像 234 个 / 3.7MB + app.js 57KB 每次整包重下

**🟠 另有** `.manifest.json` 可匿名下载（实测线上 200，返回全站 sha1 清单）——
`deploy/server.mjs` 的 `resolveSafe()` 没拦以 `.` 开头的路径段

**🟡 P2 六条**：增量同步可能漏掉官方回溯补录（已有 `⚠ 差 N` 提示缓解）、无 CI、
`shoot.cjs` 写死跨项目 Playwright 路径、`/api/health` 泄露服务器路径与 Node 版本、
两个静态服务器实现重复、README 未说明仓库数据 vs 线上数据的权威关系
