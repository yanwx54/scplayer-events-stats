# SC 赛事选手数据查询

韩国星际争霸职业选手数据查询网站。**全部数据严格限定在 eloboard 三大赛事、且只统计 2026-01-01 之后的比赛**：

| 赛事 ID | 韩文名 | 中文 / 英文 | 对局数 | 选手数 | 时间跨度 |
|---|---|---|---|---|---|
| [43](https://eloboard.com/events/43) | 메이저 프로리그 | 职业联赛 / Major Pro League | 2,175 | 51 | 2026-01-02 ~ 2026-09-17 |
| [33](https://eloboard.com/events/33) | K리그 | K联赛 / K League | 1,376 | 69 | 2026-01-02 ~ 2026-09-15 |
| [64](https://eloboard.com/events/64) | 준메이저 프로리그 | 半职业联赛 / Semi-Major Pro League | 453 | 39 | 2026-01-01 ~ 2026-08-30 |

合计 **4,004 场对局 / 86 名选手 / 本赛季 7 张地图**。

原始数据仍完整保留（`data/raw/` 含 2021 年以来的 28,161 场），改 `scripts/build-db.mjs` 里的
`CUTOFF` 一个常量即可调整统计起点，无需重新抓取。

| 赛事中文名 | 用户指定 | 메이저 프로리그 → **职业联赛**；K리그 → **K联赛**；준메이저 프로리그 → **半职业联赛** |

| 地图展示范围 | `docs/地图翻译规则.md`「本赛季地图」 | 所有地图板块只展示本赛季（2026 下半年）的 7 张地图 |

- 当前 86 名参赛选手中 **52 名**在名字文档内（覆盖 98.4% 的出场场次），其余 34 名都是零星出场。
- 本赛季 7 张地图：态度、八角笼、击倒、奥德赛、无色命运、艾洛斯、后室。

  选手「对局记录」里这些对局仍会列出，地图名后标注「·非本赛季」以便区分。


## 功能

- **总览** — 赛事分布、出场 TOP12、胜率榜、ELO 榜、热门地图
- **选手排行** — 86 名选手可按赛事 / 种族 / 场次门槛筛选，按场次、胜负、胜率、ELO、ELO 净变排序
  - **选手名显示中文名**（并列小号韩文原名，悬停可见韩文名 / 英文 ID）
  - **搜索支持韩文名、中文名、英文 ID、数字 ID** 四种输入
  - **日期时间段**：全部 / 近 7 天 / 近 30 天 / 近 90 天 / 近 1 年 / 自定义起止日，且可与赛事筛选叠加。
    切换后表格中的场次、胜负、胜率、ELO 净变都会**按所选区间重新汇总**（不是简单过滤行）；
    该区间内没有出场的选手不会进入排行
- **选手详情** — 五项标签页
  - 总览：分赛事战绩、种族对抗、近期状态、**月度走势图**（柱=出场数，线=当月胜率）
  - 地图：该选手在本赛季各张地图的场次与胜率
  - 对抗：对手种族对抗表 + 地图胜率分布
  - 对手：全部交手过的对手及其 H2H 战绩（点击进入双方对战），支持三语搜索
  - 对局记录：全部比赛，可按赛事筛选、按地图/对手搜索、分页浏览
- **双方对战** — 任选两名选手，查看总比分、分地图/分赛事交手、最近 20 次结果与全部交手记录
  - 选手选择器支持韩文名 / 中文名 / 英文 ID / 数字 ID 搜索
  - **日期时间段**：同样支持全部 / 近 7·30·90 天 / 近 1 年 / 自定义，比分与全部交手列表同步收敛；
    无交手的区间会给出空状态提示
  - **交手记录**为单行表格，每行只保留 4 项：结果徽标 / 日期 / 对阵 / 地图（胜者深色、负者灰化）；
    整体分**两栏**展示，**先填满第一栏再排第二栏**（第一栏放最近的比赛），窄屏（≤900px）自动并为一栏
- **地图情报** — 本赛季 7 张地图的总场次，以及 **6 个方向的种族对抗胜率**
  （`ZvP` `ZvT` `PvZ` `PvT` `TvZ` `TvP`，表头按第一个种族分成虫族 / 神族 / 人族三组），外加同族对抗场次
  - 胜率口径：每列只统计该方向中**前者**的胜率 —— `ZvP` = 虫族对神族的胜率，`PvZ` = 神族对虫族的胜率，依此类推
  - 同一场比赛会同时计入两个相反方向，因此 `ZvP` 与 `PvZ` 场次相同、胜率互补合计 100%（build-db 内置该自检）
  - 同族（ZvZ / PvP / TvT）不计胜率；每格附「场次」小字与胜率条，≥55% 标绿、≤45% 标红

## 数据口径说明

- **所有统计均从这三个赛事的比赛记录重新计算**，不含其他赛事。
- **只统计 2026-01-01（含）之后的比赛**，起点由 `scripts/build-db.mjs` 的 `CUTOFF` 常量控制。
- **官方 ELO**（选手页与排行中标注为「官方 ELO」）是 eloboard 站点当前的全局 ELO 值，仅作参考，**不是**这三个赛事内的计算值。
- **ELO 净变** 才是本口径内的指标：把该选手在这三个赛事中每局的 `elo_delta` 按胜负取符号后累加。
- 赛制绝大多数为单局（`단판`），一场比赛 = 一条记录 = 双方各计一场。
- 数据自检：所有选手胜场总和 = 负场总和 = 4,004；分赛事场次分别为 4,350 / 2,752 / 906，均等于该赛事对局数 ×2。

## 日期时间段筛选的实现

区间筛选若每次都去遍历选手明细（86 个文件、2.1MB）会很慢，因此 `build-db.mjs` 额外产出一份
`public/data/daily.json`：

- 结构：`days: ["2026-01-01", ...]` 日期轴 + 稀疏桶 `p[选手id] = [[赛事id, 日期下标, 场次, 胜场, ELO净变], ...]`
- 粒度是「**日期 × 赛事**」，所以「赛事 + 日期区间」可以任意组合，无需为每种组合预计算
- 前端对日期轴二分（`lowerBound` / `upperBound`）定位下标区间后线性求和，复杂度 O(桶数)，实测切换无感知
- 当区间为「全部」且未选赛事时，直接复用 `index.json` 里已算好的总量，不再走桶求和
- 区间条的可选下限即数据起点 `CUTOFF`；选在起点之前的区间会显示「没有比赛记录」

`scripts/verify-range.mjs` 会抽取 64 组「赛事 × 日期区间」（含早于 `CUTOFF`、应被自动钳制的组合），
把桶求和结果与原始比赛记录逐项复算比对，全部一致才输出 `RANGE_OK`。

## 修改译名 / 调整地图范围

1. 改 `docs/韩国选手名字.md` 或 `docs/地图翻译规则.md`（表格里加行即可）
2. 把对应内容同步到 `scripts/build-db.mjs` 顶部的 `PLAYER_ROWS` / `MAP_ROWS` 常量
   （脚本不解析 Markdown，是为了避免引入运行时依赖；两处保持一致即可）
3. `npm run build && npm run verify` 重建校验

地图范围由 `MAP_ROWS` 下方的 `SEASON_ROW_IDX` 决定（当前指向「2026 下半年」的 7 张）。
数据起点改 `CUTOFF` 常量。

## 使用

```bash
# 预览（零依赖）
node server.mjs            # → http://127.0.0.1:5178

# 每日增量同步（推荐）
npm run sync               # 增量抓取新对局 + 补选手/头像 + 重建数据库
npm run sync:full          # 全量重抓（数据异常时使用）
npm run verify             # 数据一致性校验
npm run verify:range       # 日期区间分桶求和校验
npm run backup             # 提交并推送到 GitHub

# 全量重建（需要能访问 eloboard.com）
npm run fetch              # 抓比赛 + 选手 + 头像
npm run build              # 生成 public/data/
```

`public/` 是纯静态目录，可直接部署到任意静态托管。

## 每日自动同步 + 备份

已配置每日 **10:00** 自动运行（WorkBuddy 自动化「SC三大赛事数据每日同步」）：

```
scripts/sync.mjs  →  scripts/verify.mjs  →  scripts/verify-range.mjs  →  scripts/git-backup.mjs  →  中文简报
```

### 增量同步策略（`scripts/sync.mjs`）

1. 从 `offset=0` 开始分页拉取（官方按最新在前排序），每页与本地已知 `match id` 比对。
2. **最近 400 条始终重新抓取**（纠错窗口，覆盖官方对近期记录的修正）。
3. 越过窗口后，遇到「整页都已存在」即判定到达增量边界并停止。
4. 合并规则：**同 id 以新抓到的为准**，本地多出的旧记录保留 —— 只增不减 + 近期窗口纠错。
5. 自动补抓新出现的选手元数据、下载缺失头像，最后重建 `public/data/`。
6. 结束时输出 `SYNC_OK`；若某赛事本地条数少于官方 `x-total-count`，会提示改用 `--full`。
7. **内容级变更检测**：合并后与合并前逐字节比较，无实质变化时不写盘、也不重建 `public/data/`
   （避免 `meta.builtAt` 这类时间戳造成每天一次的无意义提交）。

实测：无新数据时约 2.5~5 秒完成（每赛事仅 2 页）。

### GitHub 备份（`scripts/git-backup.mjs`）

- 无变更时跳过（输出 `GIT_BACKUP_SKIP`），不产生空提交
- 推送失败自动退避重试 4 次（SSH 到 github.com 会间歇性 Connection reset）
- 提交信息按改动内容生成：只有 `public/data/`、`public/avatars/` 变化时用 `chore(data): 同步 <日期>`，
  涉及脚本/文档则用 `chore: 同步 <日期>`
- 推送后校准本地追踪引用；末尾输出 `GIT_BACKUP_OK`

仓库：<https://github.com/yanwx54/scplayer-events-stats>

### 版本控制约定

`.gitignore` 排除了 `data/raw/`（21MB 抓取缓存，每日整体重写，入库会让仓库快速膨胀；
缺失时 `sync.mjs` 会自动全量重抓）、`shots/`（自检截图）与 `node_modules/`。
`public/data/` 与 `public/avatars/` **入库**，克隆后即可直接运行站点。
